# Cycle 002 alert-parity-splunk-grafana 設計の経緯

## Round 0（2026-10-04、main(fable-5.1) / effort: high）

### 前提になった会話

- ユーザーの依頼: Splunk と（OpenSearch + Prometheus）のアラートのコリレーションの比較を PoC でしたい。Splunk と Grafana でアラートを揃えたい。もしくは、できること・できないことを把握したい。
- 調べた結果、両方にルールがある種類が 1 つも無かった。BGP / IS-IS の状態は文字列なので Prometheus に入っていなかった。

### 却下した案

- **Telegraf で数値の field と機器名のタグを足す。** Kafka、生データ、Splunk に届くデータまで変わる。整形が要るのは Prometheus と OpenSearch だけ。
- **Grafana で trap の linkDown を無理に作る**（取り込みで field を正規化する）。このサイクルは「自然に書けるものだけ」。
- **gNMI の on_change に heartbeat を付ける**（60 秒ごとに送り直させる）。Prometheus は楽になるが、Splunk のサーチが毎分すべてのセッションの知らせを出すようになる。
- **`alert_events` に列 `rule` を足す。** cycle 001 のテーブルを作り直すことになる。detail の末尾で足りる。
- **既定は変えず、比べるときの設定を文書に書く。** ユーザーの決定と違う。
- **Grafana の評価を 30 秒のままにする。** ユーザーの決定と違う。
